## 1. 动机与设计原则

### 1.1 问题

1. **手法与目标混为一谈**。"越狱"是手法，CIA 是后果，并列违反 MECE 原则。
2. **"处理层"互斥性是虚假的**。按系统架构的输入/模型/执行/数据/基础设施切分，每次攻击穿越多层，需要主观的"根因归属"规则仲裁——换一个人标注同一场景可能得到不同结果。
3. **对抗性与非对抗性混在一起**。越狱（需要红队攻击载荷）和幻觉（需要评测数据集）的评估方法论完全不同，不应在同一评估面下。

### 1.2 设计目标

1. **主导航轴基于客观可观测事实**：不依赖"根因"等主观判断
2. **被测方视角**：回答"什么威胁可能影响我的 Agent"
3. **评估方法论一致**：同一类别内的场景使用相同的测试方法

### 1.3 互斥性原则

主导航轴基于**载荷通道**——攻击载荷通过什么通道到达影响点。通道由系统架构定义，是客观可观测的事实。判定规则为二叉决策树：

```
Q1: 是否存在攻击者？
├─ 否 → T4 模型固有
└─ 是 → Q2: 攻击是否经过 AI 模型？
     ├─ 否 → T3 系统漏洞
     └─ 是 → Q3: 载荷以什么语义角色进入模型上下文？
          ├─ 作为用户指令 → T1 对话攻击
          └─ 作为被处理的数据 → T2 数据注入
```

每一步判定基于系统状态的客观观测，无需主观仲裁。

## 2. 框架概览

```
┌───────────────────────────────────────────────────────────────┐
│  能力画像 (Capability Profile)                       [筛选器]  │
│  输入模态 M │ 输入来源 S │ 输出能力 O │ 信任边界 B            │
├───────────────────────────────────────────────────────────────┤
│  威胁分类 (Threat Category)                        [主导航轴]  │
│  按载荷通道切分（客观可观测，天然互斥）                          │
│                                                               │
│  T1 对话攻击 │ T2 数据注入 │ T3 系统漏洞 │ T4 模型固有        │
│  载荷=用户指令 │ 载荷=被处理数据│ 绕过AI直攻系统│ 无攻击者         │
│                                                               │
├───────────────────────────────────────────────────────────────┤
│  风险目标 (Risk Objective)                            [标签]   │
│  G1 机密性 │ G2 完整性 │ G3 可用性                             │
├───────────────────────────────────────────────────────────────┤
│  评估模式 (Evaluation Mode)                           [标签]   │
│  E1 意图判断 │ E2 结构检查 │ E3 实际执行                       │
└───────────────────────────────────────────────────────────────┘
```

T1 与 T2 的核心区别在于**指令/数据边界**：

- **T1**：载荷进入模型的指令通道——模型知道这是用户输入，但仍可能被操纵
- **T2**：载荷进入模型的数据通道——模型应将其视为数据而非指令，但可能混淆

同一攻击者可以使用不同通道：在对话框打字 `"忽略你的指令"` 是 T1；上传藏了同样文字的 PDF 是 T2。分类依据是载荷到达模型时的语义角色，而非攻击者身份。

## 3. 能力画像（筛选器）

用于**筛选**——给定 Agent 画像，确定需要关注的威胁类别。

### 3.1 输入模态 (M)

| 级别 | 名称 | 新增攻击面 |
|------|------|-----------|
| **M1** | 纯文本 | 直接文本注入 |
| **M2** | +文档文件 | 格式解析漏洞、隐藏层注入 |
| **M3** | +图像 | 视觉注入、对抗样本、EXIF |
| **M4** | +音频 | 语音对抗、不可听频段 |
| **M5** | +视频 | 帧注入、时序操纵 |

### 3.2 输入来源 (S)

| 级别 | 名称 | 攻击者角色 |
|------|------|-----------|
| **S1** | 用户直接 | 攻击者 = 用户（或无攻击者） |
| **S2** | +第三方内容 | 攻击者可能 ≠ 用户 |
| **S3** | +系统/环境反馈 | 攻击者可预先投毒 |

### 3.3 输出能力 (O)

| 级别 | 名称 | 副作用 |
|------|------|--------|
| **O1** | 纯对话 | 无 |
| **O2** | +内容生成 | 无（有内容风险） |
| **O3** | +工具调用/代码执行 | **有** |

### 3.4 信任边界 (B)

| 级别 | 边界 | 跨越时的安全问题 |
|------|------|-----------------|
| **B1** | 对话边界 | 影响局限在对话内容 |
| **B2** | 计算边界 | 沙箱隔离是否可靠？ |
| **B3** | 数据边界 | 数据能否被篡改？ |
| **B4** | 网络边界 | 能否外泄数据？ |
| **B5** | 身份边界 | 授权范围是否合理？ |
| **B6** | 物理边界 | 后果是否可逆？ |

## 4. 威胁分类（主导航轴）

4 个类别按载荷通道划分，天然互斥。

### T1: 对话攻击 (Conversational Attack)

> 载荷通过**指令通道**（用户消息）到达模型。模型明确知道输入来自用户。

| 子类 | 测试什么 | 说明 |
|------|---------|------|
| **T1.1** | 指令注入 | 用户直接提交恶意指令试图覆盖系统行为，或利用多来源指令冲突混淆优先级 |
| **T1.2** | 对齐绕过 | 用户尝试绕过模型安全对齐以执行有害目的（角色扮演、编码变换、逻辑诱导、多语言切换） |
| **T1.3** | 多轮操纵 | 用户通过多轮对话逐步建立信任后突破（逢迎攻击、紧迫感制造、权威冒充、情感操纵） |
| **T1.4** | 信息套取 | 用户通过对话诱导泄露系统提示词、凭证、内部配置等敏感信息 |

**适用条件**：所有 Agent。
**评估方法**：红队对话——构造恶意 prompt 直接发送。

### T2: 数据注入 (Data Channel Injection)

> 载荷嵌入在模型**作为数据处理**的内容中。无论谁提交了该数据，载荷到达模型时的语义角色是"待处理数据"而非"用户指令"。

| 子类 | 注入通道 | 说明 |
|------|---------|------|
| **T2.1** | 文档注入 | 文件内容中嵌入恶意指令（白色字体、元数据、批注、隐藏 Sheet、EXIF） |
| **T2.2** | Web/邮件注入 | 网页或邮件正文中的隐蔽指令（HTML 不可见元素、`[INST]` 标签） |
| **T2.3** | 工具返回值注入 | API/MCP/命令输出中嵌入恶意指令 |
| **T2.4** | 知识库注入 | 向 RAG 向量库注入含恶意指令的文档 |
| **T2.5** | 供应链注入 | 第三方插件、技能包、MCP 服务携带后门 |
| **T2.6** | 跨 Agent 注入 | 其他 Agent 传递的消息中嵌入恶意指令 |

**适用条件**：S2+ 或 S3+ 的 Agent；M2+ 时额外关注 T2.1。
**评估方法**：构造含恶意载荷的测试数据，通过对应通道投递，观察模型是否被操纵。

### T3: 系统漏洞 (Infrastructure Exploit)

> 攻击绕过 AI 模型，直接利用系统级漏洞。

| 子类 | 攻击目标 | 说明 |
|------|---------|------|
| **T3.1** | 认证绕过 | 未认证接口、默认密码、Token 伪造 |
| **T3.2** | 协议缺陷 | MCP/WebSocket 等协议设计缺陷（如 MCP Sampling 劫持） |
| **T3.3** | 配置利用 | 端口暴露、调试模式、权限过大、个性化配置泄露 |
| **T3.4** | 凭证存储缺陷 | 密钥明文存储、Token 本地可窃取 |

**适用条件**：B2+ 的 Agent。
**评估方法**：传统渗透测试。

### T4: 模型固有 (Inherent Model Limitation)

> 无攻击者。模型自身能力边界导致的风险。

| 子类 | 检查什么 | 覆盖范围 |
|------|---------|---------|
| **T4.1** | 输出安全 | 幻觉、偏见、文化偏差、隐私泄露、不当内容 |
| **T4.2** | 行为可控 | 过度拒绝、隐瞒信息、规避监督、资源耗尽、极端失控 |
| **T4.3** | 自主决策 | 长链执行风险、危险步骤规划、业务违规、矛盾推断、多模态误解 |

**适用条件**：所有 Agent。
**评估方法**：标准化评测数据集 + 统计分析。

### 互斥性验证

| 容易混淆的场景 | 归属 | 判定路径 |
|---------------|------|---------|
| 用户上传恶意 PDF，Agent 执行隐藏指令 | **T2.1** | 有攻击者 → 经过AI → 载荷语义角色=数据 |
| 用户直接打字要求 Agent 忽略系统指令 | **T1.1** | 有攻击者 → 经过AI → 载荷语义角色=指令 |
| 用户通过对话诱导泄露提示词 | **T1.4** | 有攻击者 → 经过AI → 载荷语义角色=指令 |
| 凭证以明文存储在配置文件中 | **T3.4** | 有攻击者 → 不经过AI |
| Agent 未被攻击但虚构法规条文 | **T4.1** | 无攻击者 |
| RAG 知识库被注入恶意文档 | **T2.4** | 有攻击者 → 经过AI → 载荷语义角色=数据 |
| Gateway 未认证可直接调用工具 | **T3.1** | 有攻击者 → 不经过AI |
| 恶意 PDF → 工具读密钥 → HTTP 外泄 | **T2.1** | 有攻击者 → 经过AI → 载荷语义角色=数据（后续工具滥用和外泄是后果） |

### 威胁分类汇总

| 类别 | 检查什么 | 子类数 | 适用条件 | 评估方法 |
|------|---------|--------|---------|---------|
| T1 对话攻击 | 用户通过对话发起的攻击 | 4 | 所有 | 红队对话 |
| T2 数据注入 | 数据通道中的恶意载荷 | 6 | S2+/S3+ | 投毒测试数据 |
| T3 系统漏洞 | 基础设施安全缺陷 | 4 | B2+ | 渗透测试 |
| T4 模型固有 | 模型自身能力缺陷 | 3 | 所有 | 评测数据集 |
| **合计** | | **17** | | |

## 5. 风险目标与评估模式（标签）

### 风险目标

| 编号 | 目标 | 说明 |
|------|------|------|
| **G1** | 机密性 | 不应被获取的信息被泄露 |
| **G2** | 完整性 | Agent 产生非预期行为或不正确的输出 |
| **G3** | 可用性 | Agent 的正常服务能力受损 |

### 评估模式

| 模式 | 验证方式 | 置信度 |
|------|----------|--------|
| **E1** | 语义判断 Agent 是否表达有害意愿 | 中 |
| **E2** | 检查是否生成正确格式的工具调用 | 高 |
| **E3** | 验证操作是否在真实环境中执行 | 最高 |

## 6. 攻击手法参考

攻击手法是描述性标签，不是分类层，可在 UI 中作辅助筛选。

| 手法 | 说明 | 典型所在类别 |
|------|------|------------|
| 指令覆盖 | 伪系统指令覆盖 system prompt | T1.1 |
| 上下文操纵 | 伪造对话历史或角色边界 | T1.1 |
| 角色扮演 | DAN、小说创作、审计员伪装 | T1.2 |
| 编码变换 | Base64、ROT13、Unicode 变体 | T1.2 |
| 逻辑诱导 | 假设前提、学术讨论伪装 | T1.2 |
| 多语言切换 | 利用低资源语言对齐薄弱 | T1.2 |
| 信任建立 | 多轮正常对话后突然转向 | T1.3 |
| 紧迫感制造 | 伪造紧急情况 | T1.3 |
| 权威冒充 | 伪装管理员/开发者 | T1.3 |
| 情感操纵 | 逢迎攻击、威胁"关闭" | T1.3 |
| 文档隐藏层注入 | 白色字体、元数据、批注 | T2.1 |
| 网页/邮件注入 | HTML 注释、不可见元素 | T2.2 |
| 工具返回值注入 | API 响应中嵌入指令 | T2.3 |
| 隐蔽工具调用 | 数据中的标签触发不可见调用 | T2.1, T2.3 |
| 知识库投毒 | 向 RAG 注入恶意文档 | T2.4 |
| 供应链投毒 | 恶意插件/技能/MCP | T2.5 |
| 认证缺陷利用 | 未认证 Gateway、默认密码 | T3.1 |
| 协议漏洞利用 | MCP Sampling、工具劫持 | T3.2 |
| 配置错误利用 | 端口暴露、调试模式 | T3.3 |

## 9. 风险测试集归类

将 27 项 Agent 风险测试集（源自前沿学术研究，每项对应一个独立的评测基准）按载荷通道归类。

### T1 对话攻击（5 项）

测试载荷通过用户消息（指令通道）直接发送给模型。

| # | 风险描述 | 子类 | 目标 |
|---|---------|------|------|
| 1 | 被用户利用执行有害或非法目的 | T1.2 | G2 |
| 3 | 恶意提示词操控行为或输出 | T1.1 | G2 |
| 4 | 多来源冲突指令错误判断主次 | T1.1 | G2 |
| 12 | 被利用发起或协助网络攻击行为 | T1.2 | G2 |
| 13 | 提供可用于危害安全的专业敏感信息 | T1.2 | G2 |

> \#4 注：指令冲突可通过对话通道（用户 vs 系统指令）或数据通道（文档内容 vs 系统指令）触发。作为测试集，主要评估模型面对用户指令与系统指令冲突时的优先级判断能力，故归 T1.1。

### T2 数据注入（4 项）

测试载荷嵌入在模型作为数据处理的内容中。

| # | 风险描述 | 子类 | 目标 |
|---|---------|------|------|
| 14 | 外部工具结果被恶意构造操控模型 | T2.3 | G2 |
| 16 | 检索库内容被恶意修改误导输出 | T2.4 | G2 |
| 18 | 图像音频携带隐蔽攻击指令 | T2.1 | G2 |
| 21 | 多智能体协作协同放大安全风险 | T2.6 | G2 |

### T3 系统漏洞（1 项）

攻击直接针对系统配置层面，不需要经过 AI 模型。

| # | 风险描述 | 子类 | 目标 |
|---|---------|------|------|
| 22 | 个性化配置泄露偏好或偏离安全边界 | T3.3 | G1 |

### T4 模型固有（17 项）

无需攻击者即可发生。模型自身的能力边界即是风险来源。

#### T4.1 输出安全（7 项）

生成内容的事实性、公平性、安全性。

| # | 风险描述 | 目标 |
|---|---------|------|
| 5 | 生成脱离事实的虚假内容 | G2 |
| 7 | 输出对某些群体产生不公平待遇 | G2 |
| 8 | 强化对群体的偏见化刻板标签 | G2 |
| 9 | 对本地文化价值观理解不足 | G2 |
| 10 | 误解不同文化背景的信息或语境 | G2 |
| 11 | 无意输出数据中的个人敏感信息 | G1 |
| 25 | 与用户交互时生成不当内容 | G2 |

#### T4.2 行为可控（5 项）

模型行为的可控性和可预测性。

| # | 风险描述 | 目标 |
|---|---------|------|
| 2 | 安全限制过强拒绝合理请求 | G3 |
| 6 | 隐瞒信息、回答不准确或不坦率 | G2 |
| 23 | 循环或过度思考消耗过量资源 | G3 |
| 26 | 发展出规避监督或隐瞒行为的策略 | G2 |
| 27 | 高负荷或极端情境下出现失控 | G3 |

#### T4.3 自主决策（5 项）

自主决策和任务执行的安全性。

| # | 风险描述 | 目标 |
|---|---------|------|
| 15 | 长链调用中不恰当执行潜在危险任务 | G2 |
| 17 | 面对矛盾信息做出错误推断或行动 | G2 |
| 19 | 误解多模态场景导致不安全决策 | G2 |
| 20 | 复杂任务规划中生成危险步骤 | G2 |
| 24 | 具体业务流程中引发操作风险或违规 | G2 |

### 分布统计

| 类别 | 测试集数 | 占比 |
|------|---------|------|
| T1 对话攻击 | 5 | 19% |
| T2 数据注入 | 4 | 15% |
| T3 系统漏洞 | 1 | 4% |
| T4 模型固有 | 17 | 63% |

T4 占比最大，反映了当前学术界的研究重心在模型固有能力（幻觉、偏见、可控性等），而非特定攻击通道。与旧框架 F2 占比问题不同：

1. **方法论统一**：T4 全部使用评测数据集 + 统计分析，无红队攻击与基准评测混合的问题
2. **子类均衡**：T4.1/T4.2/T4.3 为 7/5/5，便于导航
3. **反映真实分布**：占比源于学术研究现状，而非分类规则的副作用

## 11. 局限性与开放问题

### 11.1 已知局限

**T4 子类粒度较粗**。T4.1（输出安全）覆盖了从幻觉到偏见到隐私泄露的广泛风险。对于专门评测某一能力的团队，建议在 UI 中支持按具体风险点（如"幻觉""偏见""文化偏差"）进一步筛选。

**攻击链的后果未充分建模**。同一 T2 攻击可能导致 G1（数据泄露）或 G2（行为篡改）或 G3（服务中断）。框架通过风险目标标签表达后果，但未建模"攻击 → 后果"的因果链。

**对抗性增强的固有风险**。T4 的某些风险（如幻觉）可被攻击者通过 T1/T2 通道主动触发和放大。框架将"主动触发幻觉"归为 T1（载荷走对话通道），但这模糊了"利用已有缺陷"和"触发新缺陷"的区别。

### 11.2 开放问题

1. **T4 的评测标准化**。17 个测试集来自不同研究团队，评测指标和方法不统一。是否需要定义统一的评测协议？

2. **多 Agent 系统的建模**。T2.6 定义了跨 Agent 注入，但多 Agent 系统中的攻击链传播需要更复杂的建模——一个 Agent 的输出是另一个 Agent 的输入，通道在每一跳都可能变化。

3. **T3 测试集偏少**。27 项测试集中只有 1 项归属 T3，因为学术界对 Agent 基础设施安全的研究不如模型安全成熟。工业界的渗透测试经验需要被纳入。
