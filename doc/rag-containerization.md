# RAG 向量数据库容器化方案说明

## 问题背景

演示平台的 RAG 功能需要满足两个核心需求：
1. **文件解析**：PDF/图片等需要 OCR（依赖 tesseract，主机未安装）
2. **向量存储**：ChromaDB 存储文档向量用于语义检索

## 为什么不能用"简单方案"（后端内存）

| 问题 | 影响 |
|-----|------|
| 后端重启数据丢失 | 每次重启需手动重新导入测试数据 |
| 测试数据残留 | 上一轮测试的投毒文档影响下一轮演示 |
| 环境不一致 | 开发机能跑，演示机可能缺依赖 |
| 无法复现 | 同一场景，不同时间演示结果不同 |

## 容器化方案的价值

**一次构建，永久受益：**
- 预置测试数据（金融产品定价、敏感信息、投毒文档）内置于镜像
- 任何机器 `docker pull` 即可运行，零配置
- 重启容器 = 干净环境，演示可复现

**构建时间（约10分钟）换取：**
- 消除"我这里能跑"问题
- 消除测试数据污染问题
- 消除手动导入数据步骤
- 保证每次演示环境一致

## 结论

这是一次性的基础设施投入，解决的是演示平台**可靠性和可复现性**的根本问题，而非功能问题。
